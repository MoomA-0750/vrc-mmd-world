## 2026-09-27 MMD のモーションを外部ツールなしで Humanoid のクリップにする

- `.vmd` を ScriptedImporter で読み、MMD の標準ボーンに当てて足IKを解き、Humanoid のマッスル値にして焼く。MMD4Mecanim などの外部ツールは使わない
- 足の IK の目標も焼き、体格の違うアバターでも足が MMD の位置に着くようにした
- 焼き方を変えたら `VmdImporter.Version` を上げる決まりにした（上げないと Unity が取り込み直さず、古いクリップのまま動く）
- 根拠: 74ab89e、README「しくみ」「焼き方を変えたら」

## 2026-09-27 同期するのは時刻だけにし、踊りは各自の手元で合わせる

- 再生・停止・曲・開始時刻だけを同期し、音・お手本・踊りは各自の手元で時刻から合わせる
- ステーションのアニメーションは座った瞬間に先頭から始まり途中へ飛ばせないため、曲を区切り（既定 10 秒）に分けて区切りごとに Controller を作り、ステーションを枠ごとに2つ用意して乗り換える。降りて座り直すと一瞬立ち姿勢が見えるので、降りずに乗り換える
- 根拠: 74ab89e、a52f90f、README「踊らせ方」

## 2026-09-27 VR で踊りを体に乗せるのに、アバター SDK の部品を各自で入れてもらう

- VR では座っていても頭・手・足がトラッキングのままで踊りを上書きし、足踏みのような見た目になる。VRC Animator Tracking Control を付ければ体を踊りに任せられるが、この部品はアバターの SDK にしかない
- SDK の DLL はリポジトリに入れられないので、各自で `Assets/LocalOnly` に写してもらう形にした
- 踊りの Controller のまま降りるとトラッキングが戻らないため、全身をトラッキングに戻すだけの Controller へ乗り換えてから降りる
- 戻す Controller を1つだけの変数で渡すと、VRChat がワールドを読み込めず Udon が動かなかったので、配列で渡すようにした（切り分けの commit を挟んで判明）
- 根拠: dfb0634、455e5ce、db64327、b5d6144、7a5ca27、README「VR で踊らせるのに要るもの」

## 2026-10-02 VR の視点が揺れる問題: 移動をクリップに残し、ステーションは動かさない

- まず、振り付けの頭の動きで視点が揺れるとして、頭はトラッキングのままにする切り替えを足した（b488441）
- 仮想 VR で視点と頭の骨の位置を測り、原因は「移動を抜いたクリップで踊らせ、ステーションを軌跡どおり動かしていた」ことで、腰の揺れまでステーションごと動いて視点が揺れていたと分かった

- これで頭も踊りに合わせるのを初期で入れるようにした
- 根拠: b488441、0bf10cc、d50f7e1、5b70b99、828185b、README「踊らせ方」

## 2026-10-14 Quest の曲数は決めず、容量で知らせる。PC の見た目は Quest と同じにする

- 本人の回答: Quest の曲数の上限は、曲数ではなく容量で警告する
  - マネージャーの曲の欄に、曲の音声の合計の Android での大きさの目安を出す。70MB で注意、100MB（VRChat の Android のワールドの上限。ビルド後の圧縮した大きさ）で警告
  - 目安は Vorbis の品質から1秒あたりのビット数を見積もる（品質 0.6 のステレオで 160kbps）。Unity は今のビルド対象の大きさしか教えないので、Android に切り替えずに出すために見積もりにした。正確な大きさは BuildOnly で測る
  - 70MB にしたのは、ステージ・アバター・モーションも同じ上限に入るため（推測で決めた値。実際のビルドの大きさを見て直す）
- 本人の回答: PC 版の見た目は今のまま。本人の言葉:「今のままにしてほしいのと、あとから装飾を足したりを別でやるなどということも考えて、仕様として地面を見せたくないというのが地面を見せない意図です」
  - 床を見せないことと、PC でも軽いシェーダーを使うことを確定にした
- 根拠: https://creators.vrchat.com/platforms/android/quest-content-optimization （Android のワールドは圧縮後 100MB まで）

## 2026-10-14 タブレットの指先のずれは、機種の表ではなく立っている間に測る

- 予定「指先のずれ（`fingerOffset`）をコントローラーの機種ごとに合わせる」を、機種の表を持たずに測る形で作った
- Udon からはコントローラーの機種が分からない（`Input.GetJoystickNames` などは使えない）。一方で、立っている間はアバターの手がコントローラーに付いてくる。VRChat は機種ごとに手の位置を合わせているので、アバターの人差し指の先（先の関節から 1.5cm 先）のコントローラーから見た位置を測れば、その人の機種に合ったずれになる
- 測った値は毎フレーム少しずつ寄せてならす。指先がコントローラーから 3〜25cm になければ、手が付いてきていないとみなして捨てる
- 踊っている間（ステーションに座っている間）は、アバターの手が踊りで動くので測らない

## 2026-10-14 ほかの人の踊りの遅れを、開始位置をずらした Controller で取り戻す

- ステーションの踊りは、見ている人それぞれの手元で、座った合図を受け取った瞬間に Controller の頭から始まる。Udon からはほかの人のアバターの Animator を触れず、座っている人の Controller を差し替えても踊りは変わらない（座り直すまで）
- そこで、区切りごとの Controller に、区切りの時刻から 0.25 秒ずつ先（0.25・0.5・0.75・1.0 秒）から始まる版を作り、空いているステーションには、区切りの頭から今どれだけたったかに合う版を毎フレーム入れておく。合図が遅れて届いても、届いた時刻に合う版で踊り始める（ずれは ±0.125 秒まで）
- 自分が座るのも、区切りの頭から 1.1 秒以内なら座る（前は 0.5 秒）。遅れた分は同じ版で合わせる
- 版の数（5）と間隔（0.25 秒）は `WorldBuilder.CatchUpVariants`・`CatchUpStep`。Controller の数は 5 倍になる（区切り × パート × 2（その場）× 5）
- 試していない案: 座っている人の Controller の速さを変えて追いつかせる（Udon からほかの人のアバターの Animator のパラメータを触れないので無理）

## 2026-10-14 操作の権限を作った（見るだけ・操作・管理）

- 本人の希望（マスターが一番偉く、ほかの人も初期は操作できる。権限のある人があとから一人ひとりの権限を決められる。YamaPlayer のような仕組み）どおりに、権限を3つにした
  - 見るだけ / 操作 / 管理。マスターはいつも管理（マスターが抜けたら、次のマスターが管理になる）
  - 管理を「マスターだけ」にせず、管理の人がほかの人を管理にできるようにした（YamaPlayer の Admin に近い）
- 自分が踊る・やめる・その場・プレビューは、自分のことなので権限を問わない（見るだけの人も踊れる）。ワールドのアバターを枠に置くのは、みんなの見え方が変わるので操作の権限が要る
- 権限は `DancePermissions` が同期する（決めた人の playerId と権限の表、初期の権限）。抜けた人の行は持ち主が消す
- 画面は、新しいページを足さず、左の一覧（モデル）の見出しを押すと「人と権限」に切り替わる形にした（タブレットの大きさを変えずに済むため）
- Udon の判定はそれぞれの手元で行うので、改造したクライアントには効かない（ワールドのギミックの権限ではよくある限り）
